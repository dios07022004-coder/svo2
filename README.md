# Контракт СВО — лендинг

Статический сайт без сборки и зависимостей. Открывается двойным кликом по `index.html`
и работает как локально, так и на любом хостинге (обычная раздача статики).

## Структура

```
index.html              главная страница (вся статическая разметка и SEO-разметка)
privacy.html            политика конфиденциальности + текст согласия
favicon.svg             иконка сайта
robots.txt              правила индексации
sitemap.xml             карта сайта

assets/
  css/style.css         дизайн-система (CSS-переменные) и все стили
  img/                  оптимизированные изображения (JPEG, ≤1600px)
  js/
    config.js           ← ЕДИНАЯ КОНФИГУРАЦИЯ: телефон, соцсети, адрес, форма, карта
    icons.js            набор инлайновых SVG-иконок
    app.js              логика: модальные окна, формы, слайдеры, меню, рендер секций
    data/
      content.js        преимущества, требования, специальности, выплаты,
                        льготы, пункты отбора, этапы, обучение, документы, теги
      faq.js            вопросы и ответы (10 основных + 12 дополнительных)
      reviews.js        отзывы (демонстрационные — заменить перед публикацией)
      news.js           новости
      articles.js       статьи
    utm.js              сбор UTM-меток и источника перехода
    chat.js             виджет чата
    data/chat.js        сценарий диалога

фото для наполнения/    исходные изображения (не трогаются, остаются как есть)
```

## Что нужно заменить перед публикацией

Все места помечены комментарием `TODO`. Основное — в `assets/js/config.js`:

| Что | Где |
|---|---|
| Телефон | `config.phone` — указан `+7 (930) 079-41-13` |
| E-mail | `config.email` |
| Адрес и координаты | `config.address` |
| Соцсети и мессенджеры | `config.social` — Telegram, VK, MAX, WhatsApp, менеджер |
| Домен | `config.siteUrl`, а также `canonical`, Open Graph и `sitemap.xml`, `robots.txt` |
| Приём заявок | `config.form.endpoint` — вебхук уже подключён |
| Юр. данные оператора | `config.legalName`, страница `privacy.html` |
| Пункты отбора | `assets/js/data/content.js` → `offices` (список городов) |
| Отзывы | `assets/js/data/reviews.js` + флаг `reviewsAreDemo = false` |
| Новости | `assets/js/data/news.js` + флаг `newsAreDemo = false` |

Телефон, почта и ссылки на соцсети подставляются в разметку автоматически через
атрибуты `data-phone-link`, `data-phone-text`, `data-email-link`, `data-hours`, `data-address`,
а ряды соцсетей рендерятся в контейнеры `data-social-row`. Дублировать их вручную в HTML не нужно.

## Порядок секций

Блоки с деньгами вынесены наверх — сразу после «Преимуществ»:

`Hero → Преимущества → Выплаты при подписании → Дополнительные выплаты →
Требования → Специальности → Льготы → CTA → Порядок → Обучение → Документы →
Пункты отбора → Доверие → Отзывы → Новости → Статьи → FAQ → SEO-текст → Теги →
Официальные источники → Контакты`

Порядок пунктов в меню (десктоп, мобильное, подвал) синхронизирован с порядком секций.

## Суммы выплат

Суммы предоставлены владельцем сайта и **не проверялись** — все они помечены
`TODO: VERIFY OFFICIAL INFORMATION` в `assets/js/data/content.js`. Сверьте каждую
с действующими нормативными актами и региональными решениями перед публикацией.

Три массива в `content.js` управляют секцией выплат:

| Массив | Что выводит |
|---|---|
| `paymentHighlights` | 4 крупные цифры в начале секции (акцентный блок) |
| `payments` | карточки «из чего складывается доход»; `amount: null` → «Размер уточняется» |
| `extraPayments` | сетка дополнительных выплат; `feature: true` — сдержанное оформление |

## Добавление контента

Все разделы — это массивы данных. Компоненты менять не нужно:

* **новый вопрос FAQ** — объект в `faq.js` (`primary: true` — виден сразу, `false` — под кнопкой «Показать ещё»);
* **новая статья** — объект в `articles.js`; список поддерживает любое количество статей,
  подгрузка идёт порциями по 6;
* **новая специальность / льгота** — объект в `content.js` с уникальным `id`;
* **иконки** — имя из набора в `icons.js` (60 иконок); при неизвестном имени подставляется запасная.

## Форма заявки

Валидация: имя обязательно, телефон обязателен и проверяется по количеству цифр (10–15),
чекбокс согласия обязателен. Есть состояния default / focus / error / loading / success
и защита от повторной отправки.

## Карта

Встраивается виджет Яндекс.Карт с поиском по запросу «пункт отбора … <город>» — ключ API не требуется.
При выборе города в списке карта перестраивается на этот город. Если виджет недоступен,
показывается запасной блок с кнопкой поиска. Ключ для расширенного API выносится
в `config.map.apiKey` (в разметке не хардкодится).

## Доступность и производительность

* семантическая разметка, один `<h1>`, иерархия `h1 → h2 → h3`;
* модальные окна: закрытие по `Esc`, по крестику и по клику на подложку, ловушка фокуса,
  блокировка прокрутки, возврат фокуса, `aria-modal`;
* контраст текста проверен: для акцента на светлом фоне используется отдельный
  токен `--accent-text` (≈5.4:1);
* внешних шрифтов, библиотек и трекеров нет — только собственные CSS и JS;
* изображения оптимизированы, `loading="lazy"` везде кроме hero, у hero — `srcset` и `fetchpriority="high"`;
* у всех изображений заданы `width`/`height` (защита от сдвигов макета, CLS);
* анимации отключаются при `prefers-reduced-motion`.


## Заявки и UTM

Форма отправляет `POST` с JSON-телом на `config.form.endpoint`.
Метки снимает `assets/js/utm.js`: они читаются из адресной строки при заходе,
сохраняются в `sessionStorage` и уходят вместе с заявкой, даже если человек
успел походить по разделам.

```json
{
  "name": "Иван",
  "phone": "+79001234567",
  "source": "Первый экран",
  "page": "https://site.ru/?utm_source=yandex",
  "page_title": "…",
  "sent_at": "2026-08-11T10:00:00.000Z",
  "utm_source": "yandex",
  "utm_medium": "cpc",
  "utm_campaign": "…",
  "utm_term": "…",
  "utm_content": "…",
  "yclid": "…",
  "referrer": "yandex.ru",
  "landing_page": "/?utm_source=yandex",
  "first_seen": "2026-08-11T09:58:00.000Z"
}
```

Ловятся `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`,
а также `gclid`, `yclid`, `ymclid`, `fbclid`, `roistat`, `rb_clickid`.
Список расширяется в массиве `UTM_KEYS` в `utm.js`.

Запрос обрывается по таймауту 15 секунд — при недоступности вебхука
пользователь увидит сообщение с телефоном, а не бесконечный индикатор.

## Пункты отбора

`assets/js/data/content.js` → `offices`: 8 федеральных округов, 91 город.
Секция — аккордеоны по округам с плитками городов и живым поиском.
Адреса намеренно не публикуются: они меняются, а ошибка отправит человека не туда.
Карточка города ведёт на поиск по Яндекс.Картам и предлагает связаться с оператором.
Чтобы добавить город — впишите его в массив `cities` нужного округа.

## Чат

Кнопка в правом нижнем углу открывает переписку. Сценарий и операторы —
в `assets/js/data/chat.js`, код виджета трогать не нужно.

**Окно открывается пустым** — как настоящая переписка. Никаких заготовленных
реплик до того, как человек написал. Логика диалога:

1. пустое окно с подсказкой «Задайте свой вопрос» и кнопками частых тем;
2. посетитель пишет сообщение или нажимает подсказку;
3. оператор «читает» (пауза), затем «печатает» — статус в шапке меняется,
   в ленте появляются три точки. Длительность набора зависит от длины ответа;
4. приходит ответ по теме, следом **в ленту встраивается форма заявки**;
5. после отправки — подтверждение и ссылки на мессенджеры.

Оформление как в мессенджере: аватар собеседника у каждой реплики, время,
зелёная отметка о прочтении у своих сообщений.

### Операторы

В `operators` четыре карточки: имя, должность и аватар. Посетителю показывается
один — выбирается случайно и **закрепляется за сессией**, чтобы собеседник
не менялся посреди разговора. Разные посетители видят разных операторов.

Аватары (`assets/img/op-1…4.svg`) — рисованные, а не фотографии посторонних
людей. Если у вас есть реальные сотрудники, замените имена и подставьте
их фотографии в поле `avatar` — размер квадратный, минимум 96×96.

### Форма

Форма в чате — тот же компонент, что и на странице: та же валидация, та же маска
телефона, те же UTM-метки и тот же вебхук. Заявка приходит с меткой
`source: "Чат на сайте"`. Дублирующего кода формы нет — виджет берёт её через
`SITE.ui.formMarkup()` / `SITE.ui.bindForm()`.

Поведение неагрессивное: автооткрытия нет, подсказка у кнопки показывается
один раз за сессию и закрывается крестиком. Факт отправки запоминается
в `sessionStorage`, чтобы форма не появлялась повторно.

Адаптация: на десктопе окно 384px в углу, на смартфоне — на весь экран с учётом
`safe-area`, фон при этом не прокручивается. Пока чат открыт, нижняя панель
и кнопка вызова скрываются. Слои: чат 110 — ниже мобильного меню (120)
и модальных окон (150), поэтому диалоги всегда поверх.

## Кнопки «открыть»

Текстовых ссылок «Подробнее» на сайте нет — вместо них кнопка-иконка
(`openBtn()` в `app.js`). Название элемента уходит в `aria-label` и `title`,
поэтому кнопка остаётся понятной для скринридеров и при наведении.
Карточки специальностей, льгот, новостей и статей кликабельны целиком.

## Мобильные паттерны (≤767px)

Мобильная версия — не уменьшенный десктоп. Применены три основных паттерна:

**1. Горизонтальный свайп вместо длинных вертикальных списков.**
Класс `.scroll-mobile` превращает любую сетку в ленту с `scroll-snap` и «подглядыванием»
следующей карточки. Работает на нативном CSS, без библиотек. Применён к:
требованиям, специальностям, выплатам, доплатам, льготам, обучению, блоку доверия,
этапам оформления, пунктам отбора и статьям. Новости, отзывы и преимущества
уже используют компонент `.carousel` с той же механикой.
Подсказка «Листайте вбок» добавляется скриптом и видна только на мобильных.

**2. Модальные окна как bottom sheet.**
Ниже 600px окно приклеивается к нижнему краю, имеет «ручку», прокручивается внутри себя,
закрывается свайпом вниз (только когда содержимое прокручено в самый верх), крестиком,
`Esc` и тапом по подложке. Учтены `env(safe-area-inset-*)`.

**3. Аккордеон FAQ.**
На мобильных вопрос раскрывается на месте, на десктопе — открывает модальное окно.
**Ответы всегда присутствуют в DOM** (на десктопе просто скрыты стилями) — это сохраняет
индексируемость и согласуется с разметкой `FAQPage`.

Дополнительно:

* длинный SEO-текст свёрнут до 170px с кнопкой «Читать полностью» — текст остаётся
  в HTML, а не подгружается скриптом, поэтому индексация не страдает;
* горизонтальная прокрутка есть только внутри секций; у страницы её нет
  (`body { overflow-x: clip }` — именно `clip`, а не `hidden`, чтобы не сломать sticky-шапку);
* изображения карточек отдаются в двух размерах (`480w` и полный) через `srcset`/`sizes`;
* зоны нажатия — не меньше 44×44px;
* на экранах ≤359px уменьшен внутренний отступ, полоса показателей становится одноколоночной;
* учтён ландшафтный режим с низкой высотой экрана;
* для будущих широких таблиц готова обёртка `.table-wrapper` с внутренней прокруткой.
