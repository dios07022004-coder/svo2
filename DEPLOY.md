# Публикация и автодеплой

Репозиторий устроен так, что **его содержимое — это и есть корень сайта**:
`index.html` лежит в корне, рядом `assets/`, `robots.txt`, `sitemap.xml`.
Поэтому на хостинге репозиторий клонируется прямо в каталог сайта.

**Домен:** сво-консультация.рф (`xn----8sbe0aignfczgnl9b9e7b.xn--p1ai`)
**Хостинг:** reg.ru, `server233.hosting.reg.ru`, логин `u3587604`
**Корень сайта:** `/var/www/u3587604/data/www/xn----8sbe0aignfczgnl9b9e7b.xn--p1ai`

---

## Как это работает

```
компьютер ──git push──► GitHub ──cron каждые 2 мин──► хостинг обновляется
```

Хостинг сам ходит в публичный репозиторий и подтягивает изменения.
**Ключи и секреты для этого не нужны.**

Подключитесь к хостингу — ISPmanager → Shell-клиент, либо:

```bash
ssh u3587604@server233.hosting.reg.ru
```

Выполните одну команду:

```bash
curl -sL https://raw.githubusercontent.com/dios07022004-coder/svo2/main/setup-hosting.sh | bash -s -- /var/www/u3587604/data/www/xn----8sbe0aignfczgnl9b9e7b.xn--p1ai
```

Скрипт сам подберёт рабочую версию git, развернёт сайт и поставит задание cron.

## Повседневная работа

```bash
cd "/Users/komkova/Desktop/sites/свосео3"
git add -A
git commit -m "Что изменил"
git push
```

Через пару минут изменения на сайте. Правки контента — это обычные файлы
в `assets/js/data/`, отдельная сборка не нужна.

Нужно обновить сайт немедленно, не дожидаясь cron:

```bash
ssh u3587604@server233.hosting.reg.ru '~/svo2-pull.sh'
```

## Мгновенный деплой через GitHub Actions (по желанию)

В репозитории лежит `.github/workflows/deploy.yml` — он обновляет сайт
за ~20 секунд после push. Для работы нужен SSH-ключ.

**Ограничение этого хостинга:** файл `~/.ssh/authorized_keys` здесь является
каталогом, которым управляет панель, — дописать ключ через shell нельзя.
Добавлять нужно через ISPmanager → **SSH-ключи** (или «Пользователи» → ваш
пользователь → SSH-ключи).

Публичный ключ уже создан локально:

```bash
cat ~/.ssh/regru_deploy.pub
```

После добавления ключа в панель заполните секреты в GitHub
(`Settings` → `Secrets and variables` → `Actions`):

| Имя | Значение |
|---|---|
| `REGRU_HOST` | `server233.hosting.reg.ru` |
| `REGRU_USER` | `u3587604` |
| `REGRU_PATH` | `/var/www/u3587604/data/www/xn----8sbe0aignfczgnl9b9e7b.xn--p1ai` |
| `REGRU_SSH_KEY` | содержимое `~/.ssh/regru_deploy` целиком |

Приватный ключ в буфер обмена: `cat ~/.ssh/regru_deploy | pbcopy`

Cron при этом можно оставить — он подстрахует, если workflow не сработает.

## Если что-то пошло не так

**«Каталог не найден»** — перепроверьте путь в ISPmanager → Сайты →
«Корневая директория».

**«Не нашёл git новее 1.8»** — системный git 1.7.1 не работает с GitHub.
Включите git2192 в панели или обратитесь в поддержку reg.ru.

**Сайт не обновляется** — проверьте задание:
`crontab -l | grep svo2` и запустите вручную: `~/svo2-pull.sh`

**Сайт не открывается** — в корне могла остаться заглушка хостера.
Проверьте `ls -la` в каталоге сайта.

## Что не попадает в репозиторий

Смотрите `.gitignore`. Исключены папки `фото для наполнения/`
и `картинке для операторов/`: они весят больше 11 МБ, на сайте не используются
(там оптимизированные копии в `assets/img/`), а при клоне в корень сайта
стали бы доступны по прямой ссылке. Среди них есть сток с водяными знаками
и фотографии реальных людей — публиковать их нельзя.

## Про вебхук приёма заявок

Адрес вебхука лежит в `assets/js/config.js` и попадает в репозиторий.
Это не утечка: файл всё равно отдаётся браузеру каждого посетителя, так что
адрес виден любому, кто откроет исходники страницы. Но раз он публичный —
на стороне n8n имеет смысл поставить ограничение частоты запросов и проверку
данных, иначе в CRM можно накидать мусорных заявок.
